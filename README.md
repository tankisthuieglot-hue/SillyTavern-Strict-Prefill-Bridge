# Strict Prefill Bridge для SillyTavern

Расширение возвращает управляемый поэтапный CoT для Gemini 3.6+ (где настоящий префилл удалён из API): двухпроходный режим заполняет ваш шаблон рассуждения отдельным скрытым запросом и обусловливает им основной ответ. Также доступен одиночный режим «строгий префилл» через Structured Outputs.

## Двухпроходный CoT (основной режим)

Начиная с Gemini 3.6 API отвергает запросы, заканчивающиеся на модельный ход, — настоящий префилл невозможен на стороне клиента. Двухпроходный режим эмулирует его:

1. **Первый проход (скрытый quiet-запрос).** Расширение отправляет всю беседу плюс инструкцию «заполни шаблон рассуждения по шагам» через текущее подключение. JSON Schema с `enum` гарантирует, что ответ начинается с открывающего тега (по умолчанию `<think>`). Нативное мышление модели работает как черновик, а видимый ответ — заполненный по шагам шаблон (например, {1}–{17} из Emotionalism CoT).
2. **Второй проход (основной ответ).** Готовый блок `<think>…</think>` добавляется в промпт как предыдущее сообщение ассистента, за ним следует инструкция «пиши финальный ответ на основе завершённого рассуждения». Итоговое сообщение сохраняется как `<think>…</think>` + ответ — как в эпоху префилла: рассуждение видно, редактируемо и остаётся в контексте следующих ходов.

Настройки режима: открывающий тег, лимит токенов CoT-запроса (по умолчанию 16384), минимальное число символов (анти-лень: применяется и к CoT-запросу) и необязательное принудительное начало финального ответа через Schema. Работает для Normal, Regenerate и Swipe; Continue использует одиночный строгий префилл. Если первый проход не удался, расширение предупредит и откатится на одиночный режим. Использует два API-запроса на ответ; для Gemini рекомендуется выключить стриминг.

## Как работает одиночный режим (Structured Outputs)

- Для Google AI Studio и Vertex AI расширение задаёт JSON Schema с двумя полями: `prefix` и `content`. Поле `prefix` имеет единственное допустимое значение через `enum`, а `propertyOrdering` ставит его перед продолжением.
- Для OpenAI-совместимых источников используется строковое поле с regex `pattern`, требующим точного префикса в начале.
- Модель генерирует структурированный объект. Расширение распаковывает его в обычный текст во время стрима и перед сохранением сообщения.
- Одиночный режим форсирует только начало видимого ответа; содержательное заполнение шаблона рассуждения обеспечивает двухпроходный режим.

## Поведение

- Двухпроходный режим включён по умолчанию и использует два API-запроса на каждый Normal, Regenerate и Swipe. Если предварительный запрос завершился ошибкой, расширение показывает предупреждение и выполняет обычный строгий префилл без сгенерированного CoT.
- Во втором запросе показ нативной сводки thinking отключается, чтобы перед ответом не появлялись два блока рассуждений. Внутреннее мышление модели и выбранный Thinking Level при этом сохраняются.
- При Continue новый префилл добавляется в продолжение текущего сообщения (одиночный режим).
- Для прямых Google AI и Vertex AI в одиночном режиме можно задать минимальное число символов после обязательного блока. Это не даёт Gemini законно закрыть JSON слишком рано; `0` отключает ограничение, для длинных трекеров попробуйте `16000–24000`.
- Для прямых Google AI и Vertex AI двойные кавычки внутри блоков `<info>...</info>` временно кодируются перед JSON-запросом и автоматически восстанавливаются в ответе.
- Первый проход использует сырой ответ `generateRawData`, поэтому пользовательские Regex, стоп-строки и очистка обычного AI Output не могут отрезать начало сгенерированного CoT.
- Префилл сохраняется буквально, включая пробелы, Unicode и переносы строк.
- Нативное мышление Gemini, Reasoning Effort / Thinking Level, лимит выходных токенов, модель и семплинг не изменяются.
- Оба запроса идут через выбранный в SillyTavern провайдер и уже сохранённые настройки подключения. Расширение не читает ключи и не обращается к отдельному внешнему серверу.

## Совместимость

- Google AI Studio и Vertex AI: строгий `enum` в обоих режимах.
- NanoGPT: отдельные поля `prefix` + `content` с `enum`, без несовместимого regex `pattern`. Если конкретная модель или выбранный маршрут NanoGPT не поддерживает Structured Outputs, провайдер всё равно не сможет гарантировать префилл.
- OpenRouter и другие OpenAI-совместимые источники: `json_schema` с regex, если выбранный маршрут действительно исполняет Structured Outputs.
- Прямой Anthropic в SillyTavern 1.18 не активируется: текущий поток ответа не возвращает forced-tool input как обычный текст. Для Claude используйте OpenRouter или другой OpenAI-совместимый маршрут со Structured Outputs.
- Если провайдер игнорирует ограничения Schema, несовпадающий префилл не распаковывается. Двухпроходный режим не может обойти отсутствие настоящей поддержки Structured Outputs у маршрута.

Structured Outputs не отменяет блокировку запроса системой безопасности провайдера. Если провайдер не вернул ответ вообще, расширению нечего распаковывать.

## Установка

В SillyTavern откройте **Extensions → Install extension** и вставьте адрес:

```text
https://github.com/tankisthuieglot-hue/SillyTavern-Strict-Prefill-Bridge
```

Для ручной установки скопируйте рабочие файлы расширения в:

```text
SillyTavern/data/default-user/extensions/strict-prefill-bridge
```

Перезапустите SillyTavern или обновите страницу. Настройка появится в панели Extensions под названием **Strict Prefill Bridge**.
